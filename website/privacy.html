Data Governance & Telemetry Privacy

Data Handling & Privacy Notice

This document outlines the exact data collected, stored, and processed by the VORTEX AI platform, derived directly from our actual codebase, database schema, and serverless hosting architecture.

Notice: This is a technical privacy disclosure reflecting current software implementation. It is marked for formal institutional legal review prior to commercial general availability.

1. Information We Collect

VORTEX AI collects and processes only the minimum data required for secure operator authentication and read-only telemetry monitoring:

  • Authentication Identifiers: Operator email address, Supabase user UUID, assigned authorization role (ADMIN, SUPER_ADMIN, or standard authenticated operator), and cryptographically signed session tokens (HS256 JWT stored in the browser's localStorage).
  • Read-Only Broker Telemetry: MT5 account numbers (e.g. 26179878), broker server names (e.g. VantageMarkets-Demo), balance, equity, margin, free margin, currency, authoritative trade mode (DEMO / REAL), open position tickets, and recent trade deal history.
  • Infrastructure Access Logs: Standard HTTP request logs generated by Vercel edge functions, including client IP address, user-agent, timestamp, and HTTP response status codes.

2. What We Explicitly NEVER Collect or Store

Our zero-trust architecture strictly isolates broker authentication secrets:

  • NO Broker Trading Passwords: MetaTrader 5 account passwords and investor passwords are never entered into the website, transmitted over the API, or stored in our database.
  • NO Bank or Payment Information: VORTEX AI does not collect credit cards, bank account routing details, or payment card information.
  • NO Client-Side Private Keys: Service role keys and HMAC signing secrets remain strictly server-side on Vercel and are never accessible to client browser JavaScript.

3. Third-Party Sub-Processors & Hosting Infrastructure

VORTEX AI utilizes the following enterprise cloud infrastructure providers:

  • Vercel Inc.: Hosts the static web assets and serverless edge functions under project vortexbot-ai. Data processed includes edge API requests and JWT verification.
  • Supabase Inc. (AWS Region ap-south-1): Provides cloud PostgreSQL persistence (project xtyszeuvtfcgognkrwxv) and user identity authentication. Stores sanitized telemetry in vortex_trade_snapshots and operator profiles in vortex_authorized_operators.

4. Data Retention & Deletion

Telemetry snapshots in vortex_trade_snapshots are retained for historical charting and audit replay. Operators may request the deletion of their user profile and associated telemetry logs by submitting an administrative request. Local MT5 trading records remain entirely on the operator's private workstation in SQLite database database/trading.db.

5. Security Controls & Protection

All data in transit is encrypted using modern TLS (HTTPS). Ingestion endpoints require HMAC-SHA256 signatures with nonce deduplication to prevent replay attacks. Serverless endpoints enforce strict Row Level Security (RLS) in PostgreSQL to shield records from unauthorized access.
